# §1 引言（Introduction）

> 论文：*Compile Anything: A Neural Compiler and Runtime Architecture for General AI Task Execution*（目标会议：ASPLOS / DAC）

大语言模型（LLM）正在成为通用任务执行的核心引擎，但当前主流的智能体（agent）系统在系统结构意义上仍是一个"提示栈"：自然语言任务由冻结的大模型以 ReAct 式循环逐步解释执行——计划是即时生成的临时文本，控制流取决于模型的即兴决策，成本在事后以 token 计数结算，而计划的任何属性（类型、依赖、副作用顺序）都无法在执行前被静态检查。这种架构带来三重系统级代价。其一，推理成本高昂：每一步推理、检索乃至过滤、聚合等本可由确定性程序完成的操作，都要途经 70B 级大模型，昂贵的通用算力被摊销在最廉价的变换上。其二，串行 ReAct 循环将数据无关的调用人为串行化，端到端延迟随步数线性累积。其三，也是最基本的：缺乏系统级优化的立足点——没有可供静态分析的程序表示，指令调度、死代码消除、成本核算与副作用安全重排便都没有落点；对两个数据无关但均具副作用的调用，系统层面不存在任何机制阻止其被重排，"先扣款、后发送确认邮件"这类顺序约束在纯数据流世界中不可表达，只能依赖提示词 folklore。已有工作从不同侧面缓解该问题：[LLMCompiler] 以并行函数调用 DAG 取得最高约 3.7 倍延迟加速；[ReWOO] 通过规划与观察解耦降低约 5 倍 token 消耗；[LM-as-Compilers] 与 [CoRE] 探索以伪代码等结构化中间表示引导执行；[AIOS] 从操作系统服务层面提供智能体调度与上下文管理。但它们的"计划"仍是无类型的临时产物：依赖关系靠正则从占位符推断，程序合法性靠提示词约定，失败恢复依赖大模型重新规划——等价于一次不可校验的全量重编译。另一侧，serving 系统优化（[Parrot]、[SGLang]）与模型级联路由（[FrugalGPT]、[RouteLLM]）工作在请求粒度以下，不消费程序级语义信息，因而无法触及任务层的调度与验证。

本文的核心洞察是：**AI 任务执行与程序编译在结构上同构，编译器与体系结构领域六十年积累的工程原则——前后端分离、共享中间表示、先验证后执行、指令级成本模型、面向资源的指令调度——可以整体迁移到这一新域。**一旦自然语言任务被"编译"为带类型系统的程序表示，前端之后的一切——验证、调度、执行、成本核算——都回归为确定性的程序分析与系统调度问题。为此我们提出 compiler–runtime 分离架构：学习型神经前端（一个小模型）负责把非结构化任务意图提升（lift）为结构化程序；而程序的语义合法性、副作用顺序与执行成本，由书面规范、静态验证器与成本模型在执行前予以保证。这与 LLVM 生态的分层完全对应：前端各异而 IR 及其后的工具链是共享的确定性基础设施——用一句话概括本文立场：**前端是学出来的，前端之后全部是工程。**

基于该架构，我们实现了 Compile Anything 原型系统。TaskIR v0.1 是类型化的扁平 SSA 中间表示：分支以 guard 谓词执行加 SELECT 汇聚表达（类比 GPU/VLIW predication，无跳转、保持扁平，显著降低小模型的发射负担），验证（VERIFY 产 Bool）与有界重试回滚（retry 触发失效传播与 squash-and-replay 重执行）是一等 IR 结构而非运行时补丁。Skill ISA 定义 31 条语义技能与 2 条控制指令，每条携带延迟、token、FLOPs、能耗、内存五维成本，任务语义与具体工具名严格分层。神经编译器基于 Qwen 3B 的 QLoRA 微调（28,093 条审计语料）直接产出 TaskIR 文本；程序须经 V1–V6 六类静态不变量验证方可进入关键路径优先、按资源类组织执行器池的调度器，最终由依赖驱动运行时执行。实验上，3B 前端达到域内 validator 通过率 99.1%，其结构编译能力零样本迁移到 BFCL、τ³-bench、AgentBoard 三个从未参与训练的基准家族（结构有效性 92–99%）；但跨域语义接地急剧退化（BFCL 端到端功能语义 15.5%、τ³ 语义召回 0.6%），揭示结构编译、语义技能选择与规划深度是可分离的能力维度。在名义解析成本模型（nominal analytical model，非实测硬件能耗/延迟）下，编译后流水线的平均能耗与 makespan 分别为 70B 单发基线的 3.4% 与 37.9%，作为调度架构级分析在 §7 呈现。该架构对领域完全开放：工具调用、SQL 查询、代码生成乃至 RTL 调试等 EDA 工作负载，均可经各自 lifter 编译到同一 IR 与同一执行架构。

本文贡献如下：

1. **TaskIR v0.1 与 Skill ISA**。面向 AI 任务的类型化 SSA 中间表示：31 条 skill + 2 条控制指令，类型系统与 guard/SELECT/VERIFY/retry 结构；工具名与语义程序严格分层（两层 lowering），JSON 规范形式与文本形式经 printer–parser roundtrip 保证一致。
2. **语义审计训练语料**。71,855 条真实基准样本（xLAM/Spider/ToolBench/MBPP/HumanEval/VerilogEval 等 7 个数据集）经 adapter–lifter–validator–simulator 管线转换为 31,215 条训练语料；逐条回链原始真值的确定性语义审计达 **98.94% verified**（Tier A suspect 0.25%），MinHash 去重与组感知切分实现零跨切分泄漏。
3. **完整编译工具链**。Validator V1–V6 六类不变量（150 项单元测试；10,000 程序语义 fuzz：零非法接受、零未定义运行时失败）、依赖驱动模拟器（投机执行、回滚、trace）、资源约束 list scheduler 与五维指令级成本模型。
4. **冻结的双指标评测体系与结构/语义分离实证**。13 个外部基准（BFCL V4、τ³-bench、AgentBoard、RTL-Repo、BIRD 等，合计 132,600 任务）经污染防火墙冻结，建立"官方任务指标 + 编译侧三级闸门"双指标体系。在该体系上实证：结构编译能力零样本迁移到三个未训练基准家族（BFCL 92.4% / τ³ 98.9% / AgentBoard 91.7% valid，后者为预注册 untouched 一次性首测），而跨域语义接地急剧退化（BFCL 功能语义 15.5%、τ³ 召回 0.6%）；Phase 5C 2×2 消融进一步分离 schema 条件化（E2E +0.35pp 小幅正收益）与深度再平衡（长度↑语义不变，负结果）两个因子，主导失败定位在 retrieval–action 语义边界（EXEC_ACTION），且后端 binder oracle 上界 99.95% —— 失败可分层定位是显式 IR 架构的直接评测收益。
5. **Effect system 设计提案与实证缺口发现（proposed，未实现）**。对 τ³-bench 全量 14,834 个真实动作的效果分类（workload characterization：46.6% 可逆状态、37.8% 不可逆世界动作、3.2% 只读）表明副作用分类是真实工作负载的固有结构；据此**提出**类 MemorySSA 的 effect token 设计（效果链即调度屏障，不可逆动作禁 verify-retry），并发现 2,443 个跨类多动作任务所需的**跨类事务语义**是现有系统普遍缺失的能力。effect v0.2 与 V7 为设计提案，本文不声称已实现或已被 τ³ 验证。

本文其余部分组织如下：§2 给出背景、动机与设计原则；§3–§4 描述 TaskIR 与 Skill ISA 及成本模型；§5 呈现静态验证与 fuzz 结果；§6 阐述效果系统；§7 介绍调度与运行时；§8 介绍神经前端与语料建设；§9 为评测；§10 为相关工作；§11 讨论局限与未来工作。
