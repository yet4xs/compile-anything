# 相关工作（Related Work）

本章从四个方向梳理与 Compile Anything 密切相关的工作：LLM 驱动的任务编译与并行函数调用、Agent 工作流合成与程序化、面向结构化输出的训练方法，以及 LLM 推理调度与成本优化。贯穿这四类工作的共同局限是：任务"程序"要么是冻结大模型即时生成的无类型文本/JSON 计划，要么是开发者手工编写的流水线或搜索得到的代码，均缺乏书面规范、静态验证与指令级成本模型；本文的工具链正是针对编译器"中间端"的这一空白。

## 1. LLM 驱动的任务编译与并行函数调用

[LLMCompiler] 首次将函数调用组织为"编译—执行"两阶段：planner LLM 经 few-shot 提示输出带 `$1`/`$2` 占位符的函数调用 DAG，Task Fetching Unit 按依赖关系并发调度就绪任务，joiner 决定终止或触发重规划，相对顺序执行的 ReAct 取得最高约 3.7 倍延迟加速。[ReWOO] 更早提出规划与观察解耦：planner 在任何工具执行前产出带变量占位符的完整计划，worker 并行填充占位符，token 消耗降低约 5 倍。[Plan-over-Graph] 先将任务分解为抽象任务图、再在图之上生成可并行执行的计划，并通过两阶段训练使开源模型习得图级规划能力。[LM-as-Compilers]（Think-and-Execute）则直接把 LLM 称为编译器：先将任务"编译"为任务级伪代码，再逐实例模拟"执行"，证明结构化中间表示优于自然语言引导。在系统侧，[Parrot] 以语义变量抽象把 LLM 请求间的数据流暴露给 serving 系统，实现跨请求去重与调度优化；[SGLang] 提供结构化 LLM 程序的前端 DSL、RadixAttention 缓存复用与文法约束解码运行时。

这类工作的共同局限在于：前端是冻结的通用大模型加提示，产物是无类型的临时计划——依赖关系靠正则从占位符推断、无环性仅靠提示约定、中间值一律退化为字符串；失败恢复依赖 LLM 重新规划，相当于不可校验的全量重编译；对相互独立但带副作用的调用，系统层面没有任何机制阻止其被重排。Parrot 与 SGLang 虽提供了高效后端，但其程序须由开发者手工编写，数据流布线是显式 API 注解而非编译产物。

**本文定位**：我们不再把提示当作编译器，而是训练专用的 3B/7B 神经编译器（LoRA/QLoRA 微调），使其直接产出带类型系统的扁平 SSA 风格 TaskIR；程序经 V1–V6 六类静态不变量验证（结构、def-use、无环、类型、指令可用性、重试合法性）后方可调度执行，验证与有界重试回滚是 IR 的一等结构，而非运行时补丁。

## 2. Agent 工作流合成与程序化

[DSPy] 将 LLM 流水线表述为声明式签名与模块，其"编译"指 teleprompter 类优化器自动搜索提示与示例，流水线本体仍由开发者手写。[AFlow] 把工作流表示为算子集上的代码定义图，用蒙特卡洛树搜索在图空间中自动合成并迭代精化工作流；[ADAS] 的 Meta Agent Search 让元智能体以代码形式编写新智能体并归档复用；[GPTSwarm] 将智能体系统统一为可优化计算图，节点（提示）与边（拓扑）均通过 REINFORCE 学习。这类搜索式合成在每个领域都需要昂贵的试错循环，且产物是通用代码而非受约束、可静态推理的程序。[AgentFlow] 提出框架无关的 Agent 依赖图 IR 以支撑跨框架静态分析，验证了"智能体程序需要独立 IR"的方向，但其 IR 用于事后分析既有程序，而非作为编译目标。[CoRE] 统一自然语言、伪代码与流程图三种程序形态，以 LLM 为解释器逐单元执行并支持挂起恢复；[AIOS] 则从操作系统服务层面为智能体提供调度、上下文管理、内存与工具管理。

**本文定位**：与"生成代码或自然语言计划"的路线不同，我们为编译目标本身给出书面规范：TaskIR 是带版本号的类型化 SSA IR，分支以 guard/SELECT 谓词执行表达（无跳转、保持扁平，降低小模型的发射负担），验证与重试回滚是 IR 结构，副作用排序由类 MemorySSA 的效果链约束为调度屏障。与 [CoRE] 让 LLM 常驻解释热路径不同，我们编译"离开"LLM——非 LM 节点（FILTER、QUERY_DB 等）由确定性运行时直接执行，LLM 只在前端出现一次。

## 3. 结构化输出的训练方法

让（小）模型可靠地产出结构化可执行表示是近年活跃的方向。[WorkflowLLM] 构建 WorkflowBench（约 10.5 万指令—工作流对、覆盖 1503 个 API 与 5743 个真实工作流），经 schema 扩展、反向查询重构、剪枝与自对比训练，使 8B 模型可编排 70 余种动作类型，但其评测中的语义质量依赖 LLM 评审。[OrchDAG] 用复杂度可调的合成 plan-DAG 数据训练多轮工具编排，并以逐节点 AST 匹配加图编辑距离（GED）的 RLVR 奖励进一步优化。[IRCoder] 构建约 400 万文件的源码—LLVM IR 平行语料，证明持续预训练混入 IR 能提升代码模型的鲁棒性与指令跟随——IR 充当可迁移程序结构的枢轴语言；[LLM for Compiler Optimization] 则证明 7B 级模型经指令微调可近似无损地以文本形式产出 LLVM IR。数据质量方面，[SelfCodeAlign] 给出不依赖大模型蒸馏的自对齐配方：概念生成—候选求解—执行过滤—自我筛选；课程学习方面，[Curriculum Learning for Small Code LMs] 证明由易到难的数据排序显著提升小代码模型，[Beyond Random Sampling] 在最多 100B token 规模上报告 18–45% 的训练步数节省。此外，[Let Me Speak Freely?] 发现对未针对性训练的模型强制 JSON 等格式会大幅损伤推理能力，直接支持"训练内化格式"而非"推理时强制格式"的路线。

**本文定位**：我们的 31,215 条训练语料不是合成或蒸馏产物，而是 71,855 条真实基准样本经适配器—lifter—validator—模拟器管线的完整转换结果，并附确定性语义审计：对每条记录按原始真值回放复核，修复 lifter 后 verified 率达 98.94%（suspect 仅 1.06%，Tier A 0.254%），配合 MinHash 去重与组感知切分实现零跨切分泄漏。与 [WorkflowLLM] 的 LLM 评审和 [OrchDAG] 的合成 DAG 相比，我们的语义质量闸门是可复现的确定性检查，并直接构成三级评测（语法—验证—执行）的第一道闸门。

## 4. LLM 推理调度与成本优化

在工作流级调度方面，[Halo] 将 agentic 工作流建模为查询计划 DAG，跨批次合并共享子图以消除冗余计算，其成本模型覆盖缓存复用、prefill/decode 开销与 GPU 放置，取得最高 3.6 倍批处理加速；[SAGA] 在 64 GPU 集群上以整个工作流为原子单位调度，用约 30% 的峰值吞吐换取 1.64 倍任务完成时间，量化了调度粒度上的延迟—吞吐权衡；[Teola] 以原语级数据流图对 LLM 应用做端到端优化，验证了比任务模块更细的调度粒度。在模型档位选择方面，[FrugalGPT] 开创了 LLM 级联：廉价模型先作答、置信度检查触发逐级升级，部分任务上以最高约 98% 的成本降低匹配 GPT-4 级精度；[RouteLLM] 用偏好数据训练轻量路由器，按查询在强弱模型间选择；[Unified Routing and Cascading] 进一步将路由与级联统一为"级联路由"并给出最优性条件；[Cascadia] 用 MILP 将部署（并行度、批大小）与路由联合优化，说明级联本质上是系统问题而非单纯的模型选择技巧。

**本文定位**：上述工作要么在 GPU serving 栈内部优化（隐含工作流节点皆为 LM 调用），要么在查询粒度选择模型档位，均不消费类型化程序 IR，也未把 Python、API、数据库等非 LM 执行器视为带独立并发上限与成本的一等调度资源。我们在带类型的 TaskIR DAG 上执行经典的资源约束表调度：关键路径优先、按资源类的执行器池（LM/API/DB/Python），成本取自 Skill ISA 的每指令五维（延迟、token、FLOPs、能耗、内存）名义成本模型；VERIFY/重试构成有界投机，效果链充当调度屏障，从而把"小执行器流水线 vs 大模型单发"的权衡纳入编译期即可静态核算的框架（名义设置下能耗与 makespan 分别为 70B 单发基线的 3.4% 与 37.9%）。
