## 摘要

大模型正被用于从芯片手册生成设备驱动与初始化序列,但现有评测多在
**整理后的规格**或**参考实现**上进行,回避了三个真实问题:文档中的
要求**跨文件且跨句**、**验证动作本身有副作用**(读 shadowed 寄存器
会复位写入阶段)、以及材料不足时模型能否**拒绝而非硬答**。本文提出
一条可审计的管线:从固定版本的原始多文件手册出发,(1) 以逐字引用 +
行号 + 文件哈希抽取**机器可验证的契约表**(其中文档自身的矛盾作为
显式条目保留,不裁定);(2) 把契约编译为确定性 CPU 状态检查器,对
操作序列给出四类可重放判定(成功/违反(条款号)/证据不足/预算不可
行);(3) 同一模型、同一原文、同一预算下对照三种方法:直接生成、
带逐行出处的生成、以及"文档→结构化契约→自检→单轮修复"管线。
在 OpenTitan AES 与 SPI_HOST 两个 IP、10 个任务变体上:直接生成
2/10、带出处生成 1/10(出处行号回验 0/42 全部不符),管线 9/10 且
不提交任何含已知违反的计划;结构化抽取在 9/10 变体上完整恢复全部
契约——包括模型**主动报出文档冲突**。失败分析把差距定位到两级:
模型在跨句证据义务上系统性缺失(12/12),而管线的残余失败源于结构
自检只验证观测**存在性**而非观测**取值**。全部契约表、检查器、
冻结协议、调用账本与原始输出开源。

**关键词**:硬件手册;操作契约;来源可溯;证据条件化;LLM 评测

## 1 引言

**背景。** 嵌入式软件的正确性 hinges 在少量跨文件的手册事实上:
AES 单元在控制寄存器配置完成后、写初始密钥之前,软件必须**再次**
确认单元空闲——这一要求由程序员指南的相邻两句与共享寄存器工具文档
的一个语义段共同构成,任何单句读起来都不完整。类似的还有 SPI_HOST
"命令队列恰好还能再排一个"与"排满后必须等待"的边界。LLM 生成
驱动/初始化序列的工作增长很快,但评测大多绕开了这类**条件性证据
义务**:或用整理好的字段清单,或以参考 RTL 评分,或将"返回值正确"
当作"硬件完成"。

**缺口。** 近邻工作各有覆盖,但三个组合性质未被同时满足:
(一)**输入为原始多文件手册**,含真实的跨文件引用、冗余与矛盾,
而非整理后的规格;(二)**验证动作的副作用进入判定**——检查 shadowed
寄存器会改变其状态,因此"多查一次"不是无害的;(三)**完成声明是
条件化的**——计划只能基于实际观测到的就绪证据前进,材料或预算不足
时正确行为是拒绝,而拒绝与违反必须可区分。既有驱动验证(Termite-2)
假设设备模型已给定;NL→形式化(nl2spec)处理单句规格;嵌入式 agent
基准(EmbedBench 等)以整理后任务与行为测试为主;断言生成
(AssertLLM 系列)目标在 SVA 而非带副作用的软件访问序列。我们不
声称任何"首个";差异是上述三性质的组合与可审计性。

**本文。** 我们把"手册→可执行序列"问题重构为"手册→契约→检查器
→计划"的编译问题,并以受控实验回答:强模型在原始文档上直接规划,
究竟缺什么?管线又能机械地补回多少?

贡献(与实验一一对应):
1. **契约抽取与验证方法**(§3):逐字引用/行号/哈希三重锚定的契约
   表(两 IP 共 22 条,100% 机验),文档矛盾显式保留;
2. **确定性 CPU 检查器族**(§4):契约编译为状态机,四类判定,
   可重放轨迹;两 IP 各配契约级测试(14+6 项);
3. **三方法受控对照与失败分解**(§5):10 变体、冻结协议、逐调用
   账本;给出跨句证据义务缺失(直接法 12/12)、出处不可靠
   (0/42)、抽取完整性(9/10)、拦截与修复机制归属、以及两级
   残余缺口的精确定位。

## 2 相关工作(按近邻审计的原文边界)

**驱动验证与设备模型。** Termite-2(OSDI'14)在给定设备模型上综合
并验证驱动,显式区分硬件事件与软件确认——"返回不等于完成"已有;
其模型来自人工整理。本文不合成驱动,而是检验**从原始文档恢复可
检查契约**这一步,并把观测副作用纳入同一状态机。

**运行时保护与假设学习。** Shield synthesis(2015)在给定信号轨迹
上做最小干预保护;假设学习(TACAS'03 系)为给定模型学习环境假设。
本文的"缺失信息→保留 unknown"与其精神相近,但来源是文档原文而非
模型查询,且不把学习到的条件升格为手册承诺。

**NL→规格与断言。** nl2spec(CAV'23)把单句 NL 映射为 LTL 片段并
交互修订;AssertLLM/AssertLLM2 从全规格生成 SVA 断言并以 FPV/变异
杀灭评分。本文输出的是**带副作用的 MMIO 操作序列**与条件化完成
声明,不是断言;且我们的 oracle 不依赖参考 RTL。

**嵌入式 agent 与修复基准。** EmbedBench(ICSE'26)以整理后任务与
仿真器行为测试评 agent;DevGen 从驱动源码造 QEMU 模型;HWE-Bench
做仓库级修复。本文任务输入是未整理的原始手册,评的是证据纪律而非
任务完成率;与三者输入/行动空间/目标均不同。

**评测完整性。** 全部批次预注册冻结、逐调用账本、三次基础设施
缺陷(run1 思考预算耗尽、数组解析失败、git 误扫)均 VOID 声明并
保留记录后处置——方法论上与"评测工程"共识一致。

## 3 契约表:来源可溯的要求抽取

### 3.1 三重锚定

每条契约条目携带:逐字引用、文件、行号、文件 SHA256 前缀;全部
条目经机器回验(引用逐字存在于声明行±2 的窗口)。AES 13 条
(aes_contract_table_v1)、SPI 9 条(spi_contract_table_v1),
覆盖前置条件(AES C1/C4、SPI S1)、顺序(C3、S3)、协议(C5 两写、
S2 队列例外)、副作用(C6 读复位 phase)、错误路径(C7、S5)、
完成证据(C8、S7)与跨文件合并要求(C10)。

### 3.2 冲突保留

SPI 的 EVENT_ENABLE.IDLE 存在**两处矛盾的官方描述**(指南第 145 行
vs 寄存器表 439 行):冲突作为条目 S8 显式保留,两段引文并录,
**不裁定、不采信任何一方作为 gold**;该分支整体排除于任务范围。
实验中一个显著观察:抽取阶段模型在 3/4 变体上主动产出
CONFLICT_RETAINED 条目——结构化接口促使模型报告矛盾而非消解矛盾。

### 3.3 不猜原则

无界忙窗口(AES C13)、S2 例外的确切边界等以 unknown/open question
形式保留;检查器相应参数化(预算不可行与违反分离),不以默认值
填补。

## 4 检查器:契约到可重放判定

AESInitChecker 与 SPISubmitChecker 把契约编译为确定性状态机:
输入操作序列(read/write + 寄存器)+ 场景对象(代替 RTL 的确定性
读环境),输出四类判定——SUCCESS / VIOLATION(精确到条款号)/
INSUFFICIENT_EVIDENCE / BUDGET_INFEASIBLE——以及逐步状态快照。
两处语义裁决值得说明:(一)shadowed 寄存器两写之间的读会复位
写入阶段(C6),检查器把"两写间读后需两次全新写入"与文档允许的
恢复路径同时建模;(二)"完成"的最小 polling 证据取
READY=1 **且** TXEMPTY=1 的最终观测(S7),仅 READY 不足以宣称
发送完成。检查器对 20 项契约级测试全绿,含上述微妙路径。

## 5 受控实验

### 5.1 设置

任务族: AES 6 变体(T1-T6:忙窗口 0/3/5/10、初始非空闲、永不
就绪)、SPI 4 变体(U1-U4 同构)。场景参数对模型可见。三方法信息
输入逐字相同(对应 IP 的 4-5 份原文全文);模型 glm-5.3-flash
(temperature 0,thinking low);预算冻结;A/B 各 1 调用,C 两段
(抽取+计划)加至多一轮检查器反馈修复;oracle 为人工契约表编译的
检查器(仅评分,不提供给任何方法)。全部协议先冻结后执行,调用
逐条入账(总 78 次调用,约 5.1M tokens,含三次已声明的 VOID 批次)。

### 5.2 主结果

| | A 直接 | B 出处 | A+/B+(同预算通用修复) | A-glm-5.3 | C 管线 |
|--|--------|--------|----------------------|-----------|--------|
| AES(6) | 0/6 | 0/6 | — | 3/6 | **5/6** |
| SPI(4) | 2/4 | 1/4 | — | 1/4 | **4/4** |
| **合计** | **2/10** | **1/10** | **4/10 · 5/10** | **4/10** | **9/10**(零违反提交) |

配对精确 McNemar: C 对未修复 A 为 7-0(p=.016);对同预算通用修复的
A+/B+ 为 5-0/4-0(p=.0625/.125)——方向一致、零反例,n=10 下显著性
受限,如实报告。

### 5.3 失败分解(增益的机制归属)

**(i) 跨句证据义务是直接法的系统性盲区。** AES 12/12 直接法计划
违反 C1/C4——"配置后须再查空闲"由相邻两句 + 共享语义构成,模型
逐句可读、规划时丢失。SPI 的单句显式规则(S1/S3)直接法即好得多
(A 2/4)——**难度随文档结构可测地变化**,为基准贡献提供梯度。

**(ii) 出处要求不修复规划,且出处本身不可靠;失败是模型一般的。**
B 的逐行引文回验 0/42 全部不符(严格行精确口径);"引经据典地
犯错"。更大的 glm-5.3 无修复 4/10,C4 类违反与 flash 完全同型。
同预算的通用结构反馈修复把 A/B 提到 4-5/10——剩余对 C 的差距
恰好等于两个机制增量覆盖的任务集。

**(iii) 抽取完整性与接口效应。** 同一模型在结构化抽取接口下
9/10 变体完整恢复全部契约条目(含冲突条目)——信息可达性不是
瓶颈,交互接口是。

**(iv) 拦截-修复机制与公平对照。** 同预算通用修复(A+/B+)只回收存在性级错误;C 的修复反馈来自编译了抽取契约与场景参数的检查器(深度 k+1、取值模拟),差距归属由此与"多一轮交互"解耦。 深度感知检查(k 次忙观测 + 1 次确认
就绪——源于 T2 的教训:模型查完 k 次全忙的轮询直接前进)把全部
潜在违反转为可修复拒绝;单轮检查器反馈修复 3/3 成功。C 的每一分
增益可归属到具体机制,无一是"更多采样"。

**(v) 两级残余缺口及其机制关闭。** SPI U4(永不就绪)中 C 在**观测
到未就绪后**仍前进:结构自检验证观测存在性而非取值。将该缺口编译
为值感知模拟自检(v7,零 API 重打分 + 1 次修复)后,U4 坏计划被
正确拒绝、修复产出诚实停止计划——合并成绩 8/10 → 9/10,且两级
缺口(证据深度 k+1、观测取值)均以可归属的机制增量关闭,支持
失败分解方法本身的可操作性。

### 5.4 边界(如实)

n=10 同两族;单模型;oracle 为人工契约表(机器裁决属性同前述
纪律,声明力弱于双人独立裁决,材料开源可复核);形式模型与真实
RTL 的一致性未验证(独立后续工作);C 含修复轮而 A/B 无(修复轮
同样可加于 A/B,属公平性权衡,未做);统计显著性未报告(样本量),
证据是机制级的。

## 6 讨论

对**手册即程序**的立场:本文证据支持一个有限的强主张——当任务
的正确性取决于跨句证据义务与观测副作用时,让模型做**结构化契约
抽取**、让确定性检查器做**提交前判定**,在两个真实 IP 上把
"带错提交"降到近零并数倍提升端到端正确率;不支持的强主张是
"检查器必然提升最终正确率"(U4 反例)与"抽取等于理解"(冲突
条目的语义裁定仍超出范围)。对**基准构建**:契约表的三重锚定 +
冲突保留 + 四类判定(含拒绝)可直接迁移到其他 IP/手册族。

## 7 结论

我们把"手册→序列"重构为"手册→契约→检查器→计划",在两个
OpenTitan IP 上以受控实验证明:强模型的失败集中在跨句证据义务,
管线以机制可归属的方式回收了大部分差距,残余缺口精确定位在
观测取值语义。数据、代码、协议与账本全部开源。
