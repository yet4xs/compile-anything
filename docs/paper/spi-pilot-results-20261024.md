## 发现

1. **迁移成立**: 同一管线形态(抽取→编译检查→修复)在第二个 IP 上
   保持优势(3/4 vs 2/4、1/4),抽取在 3/4 变体上 5/5 完整——
   **含 CONFLICT_RETAINED: 模型主动把文档冲突作为条目报出**,
   与"冲突保留不裁定"的协议设计一致。
2. **任务难度谱**: SPI 族对直接生成更友好(A 2/4 vs AES 0/6)——
   S1/S3 是显式单句规则;AES 的 C4(跨句 + 二次出现)才是深坑。
   两族合并后方法差仍然清晰。
3. **C 的残余失败模式精确定位**: U4(永不就绪)中 C 的计划在观测
   READY=0 后仍提交第 2 命令——结构自检只检查"cmd1 前有读、
   cmd3 前有新读",未建模 S2 例外的边界(带着已知未就绪前进)。
   与 AES v4 的 k+1 教训同构: 下一增量是把"最近观测值"纳入
   结构自检(观测语义而非仅观测存在性)。
4. B 的 UNKNOWN_OP ×2: 模型在计划中使用了协议外的操作形状,
   按冻结 oracle 判违反——计入失败分母,如实报告。

## 边界

n=4 同族;单模型;oracle 为人工契约表;C 臂含单轮修复(A/B 无);
统计显著性未做(合并 10 变体仍小);S8 冲突未裁定,中断分支排除。

机制增量关闭,验证了失败分解的可操作性。
