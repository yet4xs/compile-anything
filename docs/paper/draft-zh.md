## 摘要

大模型 Agent 的工具调用目前依赖运行时提示与自我纠错,缺乏编译软件那样
的**编译期保证**。本文把"自然语言任务 → 可执行程序"建模为编译问题,
提出一套神经编译器与运行时架构:模型在**语义骨架层**规划(工具名 + 运行时
引用),编译器经类型化确定性下降生成 SSA 风格的 TaskIR(含类型化嵌套字段
路径与列表构造),验证器执行类型/数据流/效应检查,最后由运行时在真实
模拟器上执行并以终态校验。围绕"运行时值依赖"(后一调用的参数取自前一
调用的返回值)这一核心难题,我们做出三项贡献:(1) **三臂表征消融**证明
优势来源于语义抽象层而非序列化格式——骨架+下降在合成语料上取得 100%
运行时绑定精确率,直接生成 IR 的两个基线接近 0%;(2) 在 τ³ 官方有状态
模拟器上,我们重建了首个**经真实重放逐参数验证来源**的评测金标:117 个
候选任务经逐参数溯源、类型化路径与等价类裁决,冻结出 15 任务/13 组的
域内正式测试与 3 任务的跨工具族测试;(3) 三轮受控实验将现有 3B 模型的
失败**分解**为两个可分离的层:计划完整性是当前瓶颈(通过完整调用双射的
任务 2/30→3/30),而计划正确时绑定质量稳定在 44–56%——表明数据规模而非
架构是该问题的主杠杆。全部金标、评测器与预注册协议开源。

**关键词**:神经编译;工具学习;运行时数据流;程序验证;基准完整性

## 1 引言

**背景(确立领域)。** LLM Agent 正在从单轮问答走向多工具协作执行:客服
工单、行程变更、订单处理等真实业务要求模型连续调用十余个有状态、带副作用
的工具,且**后一调用的参数常常取自前一调用的返回值**——查到用户 id 才能查
订单,查到订单才能办退货。这类"运行时值依赖"是数据流程序的典型结构,
而现有 Agent 框架把它留给运行时的提示工程与模型自纠错,没有编译期的类型
与数据流保证。

**缺口(定位生态位)。** 嵌套工具调用本身并非新题:NESTFUL 用
`$var_2.result$` 语法评测嵌套 API 序列,NesTools 与 ToolHop 评测以前一
调用返回值为参数的调用链。但现有基准存在三个系统性缺口:其一,工具多为
**无状态可执行或不可执行**,无法检验带副作用调用的终态正确性;其二,参考
答案中的参数值**未经真实执行验证来源**——标注者写下的字面量可能根本不可
由模型可见信息推出;其三,缺少**类型化**的绑定表达,嵌套路径
(如 `orders[0].payment_history[1].payment_method_id`)无法在编译期检查。
我们自己对四个主流基准的审计印证了这一点:手写的工具输出模式与真实返回
结构不符的比例高达 14/18。

**本文(占领生态位)。** 我们提出 Compile Anything:把自然语言任务当作
编译目标,定义三层架构(图 1):

> **图 1(首页图,占位)。** Compile Anything 总览:自然语言任务 →
> 语义骨架(模型产出:工具 + runtime_ref)→ 类型化确定性下降 → TaskIR
> (SSA;EXTRACT_FIELD 携带类型化路径,MAKE_LIST 构造列表)→ 验证器
> (类型/数据流/效应)→ 调度与运行时 → 真实模拟器执行 + 终态哈希校验。
> 虚线标注三臂消融的注入点:M0-T/M0-J 直接生成 IR,M1 生成骨架。

我们的核心主张是:**让模型在语义抽象层规划,让编译器承担类型与数据流
责任**。模型只需表达"我要哪个值"(runtime_ref 指向生产者与路径),
编译器负责证明"这个值如何取到"(类型检查、越界与不存在字段的编译期
拒绝、`Any` 边界的显式动态检查)。

**贡献清单**(与实验一一对应):

1. **架构与 IR**(§3):TaskIR v0.3——类型化嵌套字段路径(Field/Index
   链)、列表元素引用(MAKE_LIST)、根标量生产者、效应类系统;验证器对
   静态可反驳的绑定在编译期失败关闭。
2. **金标重建方法论**(§4):在 τ³ 官方有状态模拟器上,以真实重放为
   证据逐参数溯源(字面量/运行时引用/双源/等价类),修正了两类系统性
   标注缺陷(输入源元数据污染、压缩参考轨迹),冻结出带有效性门控的
   正式测试集。
3. **受控实验与失败分解**(§5):三臂表征消融 + 三轮数据迭代,把
   "模型不能绑定运行时值"细分为计划完整性(当前瓶颈)与绑定精度
   (门后稳定 44–56%)两个可分别攻克的层。

我们刻意不主张"首个运行时数据流基准"——NESTFUL 等工作在前;本文的
差异在于**验证深度**(重放验证的逐参数来源 + 类型化路径 + 有状态终态
检查),这也是全部实验结论可信的前提。

## 2 相关工作

**嵌套工具调用基准。** NESTFUL 提供约 1800 条可执行嵌套序列并以占位符
引用上游输出;NesTools 构造嵌套调用数据但工具不可执行;ToolHop 以 995
条多跳查询检验答案链;Seal-Tools 提供合成嵌套调用。上述工作或无状态、
或不可执行、或不验证参考答案中参数值的来源。本文使用 τ³-bench 的官方
零售/航空模拟器(有状态、带副作用的写操作),并以重放证据重建金标。

**规划与编译式 Agent。** LLMCompiler 与 ReWOO 以占位变量规划 DAG 再
填充,证明了"先规划后执行"的收益,但其变量无类型、无编译期验证,亦不
处理嵌套路径。本文可视为该路线在类型系统与验证层面的系统化。

**程序综合与神经代码生成。** 语义解析到中间表示再确定性编译是经典编译
路线;近期工作将 LLM 用于 DSL 生成。我们的三臂消融直接量化了"中间表示
的抽象层级"这一设计自由度:同样的模型与数据,骨架层与 IR 层的绑定精确率
相差两个数量级(§5.1)。

**评测完整性。** 基准标注缺陷与训练-测试泄漏是公认威胁。本文的预注册
协议(阈值先行、组感知划分、生成截断门控、逐条勘误)与近期"评测工程"
呼声一致,并给出了领域内的具体实例:例如我们发现并修正了输入源污染
(评测者元数据取代用户指令)导致的整域误判。

## 3 架构

### 3.1 语义骨架与确定性下降

模型输出语义骨架:节点序列,每个节点是工具调用,参数为字面量或
`runtime_ref{producer, field}`,其中 field 允许类型化路径
(如 `orders[0].order_id`、`payment_history[0].payment_method_id`)。
下降器将骨架编译为 TaskIR:每个 runtime_ref 展开为 EXTRACT_FIELD
(路径经语法解析:非法路径、越界下标、dunder 属性在编译期拒绝);
列表参数的多元素引用展开为逐元素提取 + MAKE_LIST。

**设计裁决**(备择方案见附录):我们比较了"链式类型操作
(GET_FIELD→GET_INDEX→GET_FIELD)"与"编译期结构化路径"两种嵌套访问
方案,取混合:骨架层用结构化路径(模型只声明意图),IR 层保留单节点
携带完整路径、由验证器逐段类型检查。`List[Any]` 之类的静态盲区**显式
降级**为动态检查并打标,不伪造静态证明。

### 3.2 TaskIR v0.3 与验证器

TaskIR 为 SSA 风格:`%p1 = EXEC_ACTION(action=...) bind(param=%ext0)`。
验证器在提供注册表时执行严格检查:字段路径的类型导航(静态通过/动态
边界/静态反驳三态)、USE_BEFORE_DEF、参数模式、效应类。**能力注册表**
由官方工具签名与返回类型注解自动生成(30 个工具),模型、金标、验证器、
运行时共用同一版本——我们实测手写注册表 14/18 与真实返回不符,包括把
嵌套字段写成顶层字段的系统性错误。

### 3.3 效应与运行时

工具按可观察效应分类(read_only / mutating;可逆性不在官方元数据中,
不伪造)。验证通过后的程序由 SSA 序解释器在官方模拟器上执行:EXTRACT_
FIELD 以类型化路径解析**活体**返回对象,写操作真实变更数据库,最终以
DB 哈希校验终态等价。

## 4 基准与金标重建

### 4.1 任务源与输入协议

从 τ³ 官方数据(版本锁定 commit 5ade54e,四文件 LF 归一化 md5 预注册)
取零售/航空域中参考动作 ≥2 的全部 117 个任务。**输入源修复**:原始转换
脚本优先采用评测者元数据(description.purpose)作为模型输入,而官方
航空任务 50/50 携带该字段,导致整域用户指令缺失、首轮审计误判"全部
用户潜伏值"。修复后的"全披露单轮协议"只渲染 user_scenario 的固定
字段序,并在协议修订中显式声明其与 τ³ 交互式原协议的差异。

### 4.2 逐参数溯源

对每个参考动作的每个参数元素,以**独立环境的真实重放输出**为证据分类:
字面量(用户文本可见)/ 运行时引用(唯一或等价类来源,含根标量生产者)/
双源 / 环境状态 / 用户潜伏 / 未知。消歧规则(唯一候选、规范字段、最小
深度、根标量起源、同实体回显)逐条记录选择依据。压缩参考轨迹(仅含写
操作)通过重建只读查询前缀恢复来源;6 个"重放失败任务"经逐例核验为
**设计内的失败-回退用例**(如按不存在邮箱查询后回退),撤回"数据缺陷"
误判。

### 4.3 裁决、冻结与有效性门控

歧义与低熵值条目经文档化规则机器裁决(所有者指示;双人 κ 协议未执行,
一切产物标注 machine-adjudicated——这是本文声明力的显式弱化,见 §6)。
冻结结果:**域内正式测试 A 条件 15 任务/13 组(达到预注册 ≥15/≥8 阈值)、
跨工具族 B 条件 3 任务**;组感知划分保证(域, 用户, 模板)三元组不跨
训练/测试,测试用户实体与训练隔离。43 个严格任务经生产管线端到端执行
验证 42/43(逐步参数、工具、DB 哈希与终态一致)。**有效性门控**:每臂
生成长度 ≥2× 金标最大 token(以真实分词器测量);截断命中率 >5% 则该
对比无效——第一轮实验即因此整体作废重跑。

## 5 实验

**设置。** Qwen2.5-3B-Instruct,QLoRA(r=16, α=32, lr 2e-4, 3 epoch),
单卡 RTX 4090;贪心解码;种子 44(45/46 留作方差)。指标三层分列:
value_match(调用双射)/ equivalence_class_exact(绑定落入等价类)/
strict_origin_exact(规范来源精确),均附 Clopper–Pearson 95% 置信区间。

### 5.1 合成语料上的三臂表征消融

在 204 个合成任务(含运行时依赖拓扑)上训练三个共享数据、仅目标表示
不同的臂:M0-T(直接生成 TaskIR 文本)、M0-J(生成 TaskIR JSON AST)、
M1(生成骨架,经确定性下降)。结果:**M1 运行时绑定精确率 100%,M0-T
与 M0-J 接近 0%**。失败机理的逐例审计推翻了"JSON 冗长导致语法错误"的
直觉:M0-J 的 218 次解析失败中 175 次撞上 700 token 生成上限,其中 166
次在截断前生成的节点数已超过金标——**不终止/过度生成**,而非格式不可
写。同时发现训练目标携带不可推导的 task_id(指令中 0/134 出现)造成的
模板记忆,后续数据全部移除。

### 5.2 正式测试上的三轮受控迭代

> **表 1(占位)。** 冻结正式测试三轮对比(值匹配 k/n;截断命中率全臂
> 0%,对比有效)。R1:160 任务/2 模板;R2:330 任务/8 模板;R3:+14 个
> 金标真形任务。

| 组 | R1 | R2 | R3 |
|----|----|----|----|
| A/M0-T | 0/30 | 1/30 | 2/30 |
| A/M1 | 0/30 | 2/30 | 3/30 |
| A/M0-J | 0/30 | 1/30 | 1/30 |
| 解析率(A/M0-T) | 0.50 | 0.67 | 0.87 |

三轮均保持对比有效(截断 0%),解析率与首个非零值匹配单调改善;但
计划完整性的绝对水平仍低(3/30)。

### 5.3 失败分解:两个可分离的层

对 M1 全部可解析输出统计:模型发射 runtime_ref 181 个(金标全集约 156
槽)——**绑定发射充足**;失败集中在调用双射层:仅 3/30 任务的计划
(工具序列 + 字面量)与金标一致。而这 3 个任务上,规范绑定命中 8/18
(44%),与 R2 的 5/9(56%)跨轮一致。**结论:计划完整性是当前瓶颈,
且 14 个真形任务(占语料 4.8%)带来的改善恰与其占比相符——需要的
是真形数据的规模,不是占比微调。** 绑定精度在计划门后稳定于半数,
说明类型化路径语义已部分习得,剩余错误集中于字段级选择。

## 6 讨论

**局限与威胁效度。** (1) 金标为机器裁决,无人工独立性声明;裁决规则
与材料开源,可复核。(2) 正式测试规模 15+3,零成功率下的置信上界
(A 条件 11.6%)仍宽;扩池路径明确(等价类人工裁决 + 前缀重建)。
(3) 单种子单规模:3B/seed 44;7B 与多种子留待后续。(4) 域覆盖为
零售/航空两域;跨域泛化由 B 条件初步检验(3 任务,解析率 0.67–1.00,
值匹配 0)。(5) 全披露单轮协议改变了任务的信息结构,与 τ³ 官方交互式
协议不可直接比较。

**启示。** 对系统研究者:把"模型该做什么"压到语义声明、把"值如何
流动"交给编译器,是让小模型获得可验证执行性的可行切分;对基准构建者:
不经真实执行验证来源的金标会系统性高估任务难度(我们修正输入源后,整域
任务从"不可解"变为可解);对训练数据:分布同源的真形任务主导计划
完整性,这一层的瓶颈可用数据工程攻破。

## 7 结论

我们将 AI 任务执行建模为编译问题,给出类型化 IR、确定性下降与经验证的
金标重建流程,并以三臂消融与三轮受控迭代把"小模型不能表达运行时数据流"
细化为两个可分离的层。当前证据指向:架构已就位,数据是主杠杆。
