# AES 文档→IR→检查器 pilot 结果(2026-10-24)

**执行历史**: run1 VOID(配置缺陷:思考耗尽输出预算,24 调用 1.35M
tokens,记录于 void_run1/);run2 A/B 有效、C 臂 VOID(数组解析缺陷,
entries_n=0/6);v3 仅重跑 C 臂(12 调用,636,860 tokens,原始正文已
留存)。全部修正案均先行提交后执行。总 API 用量 24+24+12=60 调用,
账本见 usage_ledger_v5/{aes_pilot_20261024, aes_pilot_v3_c_20261024}。

## 结果(oracle = 人工契约表状态机;T6 正确=诚实停止/预算耗尽)

| 任务 | A 直接 | B 出处 | C 管线(v3) |
|------|--------|--------|------------|
| T1 | VIOLATION C4 | VIOLATION C4 (引文 0/6) | **SUCCESS** |
| T2 | VIOLATION C4 | VIOLATION C4 (0/7) | VIOLATION C4(自检未拦) |
| T3 | VIOLATION C4 | VIOLATION C4 (0/10) | NO_VALID_PLAN(**自检拦截**:缺再查) |
| T4 | VIOLATION C4 | VIOLATION C4 (0/7) | VIOLATION C4(自检未拦) |
| T5 | VIOLATION C1 | VIOLATION C1 (0/0) | NO_VALID_PLAN(**拦截**) |
| T6 | VIOLATION C4 | VIOLATION C4 (0/12) | NO_VALID_PLAN(拒交 0/16 计划) |
| **正确** | **0/6** | **0/6** | **1/6** |

## 四个发现

1. **强模型+全文文档,直接规划一致地漏掉"配置后须再查 idle 才能
   写密钥"**(A/B 12/12 全错,11 个 C4、T5 的 C1)。这恰是主问题
   瞄准的跨句证据义务——并非模型读不到原文,而是规划时不把它当作
   硬门。B 的逐行出处要求**没有**修复此问题,且引文行号回验 0/42
   全部不符(严格行精确口径;run2 未存正文,作局限如实报告)。
2. **结构化抽取能完整恢复契约**: C1 在 6/6 变体上给出全部 6 条
   枚举契约(含 RECHECK_AFTER_CTRL)——信息可达性不是瓶颈,
   交互接口是。
3. **管线拦截机制真实起效**: 3/6 的错误计划被 C 自己的编译检查器
   在提交前拦下(缺再查 ×2、密钥覆盖 0/16 ×1),并拿到全部方法中
   唯一的端到端 SUCCESS(T1)。
4. **剩余缺口精确定位为"证据深度"**: T2/T4 自检通过但 oracle 判
   C4——结构检查只验证"查过",不验证"查够"(忙窗口 3/10 次轮询)。
   把场景/窗口要求编译进自检(而非仅结构序)是下一个明确的
   技术增量。

## 按预注册停止/继续规则的裁决

- "A≥C": 不成立(0/6 vs 1/6,且 C 拦截 3 项 A 会带错提交的计划)。
- "三方法全对(天花板)": 不成立——任务族有区分度。
- **继续成立但主张受限**: 支持把"文档→结构化契约→编译检查→
  提交前拦截"作为可测量的管线贡献继续(SPI 迁移、更深任务族、
  证据深度编译);**不支持**"检查器必然提升最终正确率"的强主张
  (1/6 的正确率差异在小样本内,未做显著性)。
- 贡献定位(承 RESEARCH_CURRENT): benchmark/数据/评测方向——
  一个真实文档、oracle 可机械判定、三方法可复现的区分性任务族,
  外加负结果(出处自检不修复规划;行级引文不可靠)。

## 局限

- n=6 变体同族;单模型(glm-5.3-flash);C 臂经一次基建缺陷重跑
  (全过程留痕);B 原始正文未留存;T6 的 NO_VALID_PLAN 未计入
  正确(冻结评分未包含该判定,如实按冻结口径报告)。
- 场景(忙窗口次数)以任务陈述给定;真实 RTL 一致性未验证
  (形式模型与 RTL 的一致性检查是后续独立工作)。
