# v8 冻结协议:公平修复轮 + 第二模型(调用前)

目的: 堵住两处最可能的评审攻击——C 有修复轮而 A/B 无;结论是否
单模型特有。不做种子/温度重复实验(所有者指示)。

## Part 1 公平修复轮(A+/B+)

- A/B 重新生成(带原始输出留存;AES run2 未存正文,须重生成)后,
  对每个 VIOLATION/UNPARSEABLE 的初始计划给**一次**修复调用。
- 修复反馈来源 = **通用结构检查器**(与 C 管线 v6 阶段相同的
  own_check 代码、全 flags 开): 反馈只含通用规则违反描述
  (如"首命令前无读""满 2 后无新读""缺再查"),**不含**人工契约
  表、场景深度值(k+1)或观测取值语义——上界原则保持。
- 预期检验: 若 A+/B+ 借通用结构反馈即追平 C,则 C 的增益归属
  被削弱;若仍留差距,则差距归属到深度/取值两级机制(与 v4/v7
  一致)。两种结果都如实报告。

## Part 2 第二模型 A 臂(A-glm5.3)

- model=glm-5.3(非 flash),A 臂原提示,10 任务各 1 次,仅测
  "直接生成的跨句证据义务缺失是否模型特有"。
- 不做修复轮、不做 C 臂(预算边界)。

## 预算与纪律

调用 ≤ 10(A)+10(B)+≤10(A 修复)+≤10(B 修复)+10(glm5.3) = 50;
temp 0,thinking low,8196;逐调用账本 v8;评分沿用冻结 oracle 与
四类判定;任何基建缺陷按既有 VOID 规则处置。
